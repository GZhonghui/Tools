请对本仓库进行一次凭据泄露检查，并按以下流程记录结果。
只做检查并新增 Review 记录；不自动修改业务代码、忽略规则，不提交或重写 Git 历史。详细评估和建议直接在对话中报告，Review 文件只保留简短记录。

Git 命令默认只读约束（适用于整个流程，例外须先获用户明确批准）：
- 默认只允许本地查询操作，例如 status、log、show、diff、rev-parse、rev-list、ls-tree、cat-file、merge-base、for-each-ref、ls-files、check-ignore。
- 未经用户明确批准，禁止 add、commit、push、fetch、pull、checkout、switch、reset、restore、clean、stash、merge、rebase 等写操作，以及任何会修改 Git 索引、对象、引用、配置、工作区内容或远端数据的命令；也不能通过脚本或 Git 库绕过这一限制。
- Git 查询统一使用 git --no-optional-locks ...，避免 status 等查询顺带刷新索引；下文命令示例省略这个公共选项。
- 历史或对象不完整时先记录检查限制；未经批准，不执行 fetch、自动按需拉取或其他补齐数据的写操作。
- 特殊情况确需写操作时，可以向用户申请：先说明具体命令及参数、执行原因、涉及范围和预期影响，等待用户明确同意后才执行，且仅限已批准的操作。不能将“开始检查”视为写入授权；未回复或未获批准时保持只读，继续可完成的检查并如实报告限制。
- 新增或编辑 Review 文件使用普通文件编辑方式，默认不执行 git add，不暂存、提交或推送；如需例外，同样先按上述规则申请并获得明确批准。

1. 确定本次检查的截止点
- 先查看仓库说明、适用的 AGENTS.md 和 git status，保留已有改动。
- 在新增检查记录之前，用 git rev-parse HEAD 获取完整 commit ID，固定为本次截止提交 CURRENT_COMMIT。
- 日期使用用户所在时区的当天日期；如未指定时区，使用当前环境时区。
- 默认只检查 CURRENT_COMMIT 中已提交的文件快照及所选 Git 历史，不读取本地未提交内容，包括暂存、未暂存和未跟踪内容。只有用户明确指定要检查某些待提交文件时才纳入，并单独记录这些内容不属于 CURRENT_COMMIT。

2. 读取上次记录并确定 Git 历史范围
- 查找 Review/YYYY-MM-DD.md 及同日带序号的记录，按日期、序号从新到旧读取，选取最近一次完成检查的有效记录。
- 从记录正文读取“截止 commit”的完整 ID，作为 PREVIOUS_COMMIT；不要使用提交 Review 文件时产生的 commit 代替检查截止点。
- 验证两个 commit 在本地存在，并用 git merge-base --is-ancestor PREVIOUS_COMMIT CURRENT_COMMIT 确认历史关系。
- 正常增量范围为 PREVIOUS_COMMIT..CURRENT_COMMIT：不包含上次截止提交，包含本次截止提交。用 git rev-list 获取区间内的每个提交，而不是只比较两个端点的最终文件。
- 检查每个区间提交中的文件版本，覆盖新增、修改、删除、重命名及合并带入的内容。重点避免遗漏“曾加入密钥、随后又删除”的中间版本。
- 没有历史记录时，扫描本地全部可达 Git 历史，包含分支、远程跟踪分支和标签可达的已删除文件及旧版本；相同文件内容可按 blob ID 去重。
- 有历史记录时，除上述 HEAD 区间外，也核对其他本地引用；对 CURRENT_COMMIT 历史未覆盖的可达提交补查，避免漏掉其他分支。补查范围单独记录，允许重复检查。
- 若上次 ID 缺失、记录的检查不完整、commit 不存在，或上次截止点不是当前提交的祖先，不要直接套用增量范围；回退到本地可达历史全量检查，并简短注明原因。
- 若两次截止 ID 相同，说明该历史区间为空；仍检查截止提交的文件快照和其他引用，不把空区间写成新增历史已扫描。
- 检查仓库是否为浅克隆、历史是否完整；结论只覆盖实际扫描的本地历史，不声称检查了未拉取的远端提交、不可达对象或 reflog。

3. 确定文件范围及排除项
- 检查截止提交中已提交的全部项目源码、脚本、配置、文档、前端代码和依赖清单；不能只检查本次修改的文件。
- 本地忽略规则以仓库根目录及各级 .gitignore 为准，不按 env 等扩展名或文件类型另设统一豁免。被忽略且未进入 Git 历史的文件可能包含机密信息，一律不读取内容。
- 其他未提交的本地内容也不自动检查，不以全盘搜索、遍历目录或扫描缓存的方式读取。只在必要时查看文件名、Git 跟踪状态和忽略规则是否生效，不 source 配置或打印实际环境变量值。
- 用 git ls-tree -r -z CURRENT_COMMIT 枚举已提交文件，再按 blob ID 读取快照；历史同样只读取所选提交中的 blob，避免误读本地私有副本。
- .gitignore 不会移除已经提交的内容：曾经进入 Git 历史的文件，即使现在被忽略或已删除，仍需检查其已提交版本；不因此读取其本地未提交副本。已提交的 env 文件与其他文件采用同样规则。
- .git 内部元数据不作为普通项目源码遍历；Git 内容通过只读命令检查。未提交的依赖目录、虚拟环境和缓存不读取；若它们已被提交，应纳入历史检查或如实记录未覆盖范围。
- 已提交及历史中已删除的压缩包也应检查其内部文本文件；内部文本属于已提交内容，不能仅因文件名为 env 就跳过。只读处理，不执行其中内容。二进制可检查可打印字符串，但不能据此声称完成了图像、音频内容或任意编码载荷的检查。
- 只检查仓库范围，不沿代码中的路径读取仓库外的 Cookie、私钥或其他实际凭据文件。

4. 检查内容与命中复核
- 检查硬编码 Token、API Key、密码、私钥、认证头、Cookie/会话内容、带账号密码或签名参数的 URL，以及 webhook 等凭据。
- 结合关键词、常见服务凭据格式和高熵字符串扫描；同时覆盖直接赋值、命令参数、注释、示例、配置及历史提交说明。
- 人工复核所有可疑命中，区分实际凭据与占位示例、环境变量名、文件路径、依赖版本、校验和、库常量及二进制误报；不能只因出现 token 或 cookie 字样就判定泄露。
- 查看凭据的读取和输出路径，关注日志、异常、命令参数、临时文件、备份和导出文件是否可能保存敏感内容，以及这些生成文件是否可能被误提交。
- 特别复核聊天备份正文不脱敏、M3U8 保留 URL 账号密码、生成文件可能误提交等已知注意事项；只检查代码中的行为，不读取本地未提交的实际备份或生成文件。根据本次代码确认现状，不能直接照抄上次结论。
- 不运行下载、备份、发送消息、启动容器等业务脚本，也不联网验证凭据是否有效。
- 工具输出、检查记录和对话均不得复述实际凭据；发现问题时只提供文件位置、行号或历史 commit、凭据类型及脱敏后的必要信息。

5. 写入本次 Review 记录
- 在 Review/ 下新建 YYYY-MM-DD.md，例如 Review/2026-11-05.md。
- 同日已有记录时不覆盖，依次使用 YYYY-MM-DD-2.md、YYYY-MM-DD-3.md；后续检查以最新有效记录中的截止 ID 为准。
- 记录必须简短，包含：检查日期、完整截止 commit ID、上次截止 ID（如有）、实际检查的历史区间或全量范围、文件范围、排除项、检查内容、结果和是否存在风险。
- 明确截止点“包含该提交及其之前的内容”，增量区间则明确“上次不含、本次包含”；本次新建的检查记录不计入已检查内容。
- 若用户另行指定检查待提交文件，或有其他分支补查、浅克隆、无法读取的文件和未完成范围，简短说明，不能写成已覆盖。
- 提交数、文本版本数、压缩包文件数等仅在实际统计后填写，不沿用旧记录中的数字。
- 结果采用“未发现真实凭据”或“发现凭据残留”等准确表述；区分实际泄露迹象与运行后才可能发生的风险。检查不完整时写明限制，不给出全库无风险结论。
- 文件中不写详细评估、风险评级、整改方案或凭据原文；详细说明直接在对话中报告。

记录模板（按实际情况填写，删除不适用项）：

# YYYY-MM-DD 仓库凭据检查

- 截止 commit：`CURRENT_COMMIT 的完整 ID`，包含该提交；不包含本次新增的检查记录。
- 上次截止 commit：`PREVIOUS_COMMIT 的完整 ID`；首次检查写“无，首次全量检查”。
- Git 历史范围：`PREVIOUS_COMMIT..CURRENT_COMMIT`（上次不含、本次包含），或本地全部可达历史；注明其他引用补查及实际数量（如已统计）。
- 文件范围：截止提交中的已提交项目文件及上述历史中的旧版本、已删除文件、压缩包内文本；用户另行指定的待提交文件单独注明。
- 排除及限制：本地被 .gitignore 忽略及其他未提交内容默认不读取；已提交内容不因当前忽略规则或 env 文件名而排除。注明本次其他实际限制。
- 检查内容：硬编码凭据、认证信息、敏感 URL、Cookie，以及日志、备份和导出文件的凭据流向。
- 检查结果：按实际复核结果简述是否发现真实凭据或历史残留。
- 风险结论：简述有无已发现的泄露迹象及潜在风险，具体评估在对话中说明。

6. 结束前核对并口头报告
- 核对当前 HEAD 仍与固定的 CURRENT_COMMIT 一致；若期间 HEAD 变化，补齐新增范围或明确保留原截止点，不能混用范围。
- 检查新记录的文件名、日期、完整 commit ID、区间边界、统计数字与实际扫描范围是否一致，并确认没有写入凭据原文。
- 再看 git status，确认没有改动用户原有文件，也没有误将扫描产生的缓存或临时文件留在仓库里。
- 在对话中给出本次记录链接、检查截止点、是否发现真实凭据，以及必要的风险判断和建议；不自动提交检查记录。
